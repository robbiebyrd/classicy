# J 1.1: ClassicySchemaForm extracted from the ScreenSaver config form

## Problem Statement

Audit §8.2 names the ScreenSaver options form as the schema-driven pattern the Appearance panel should use, but `ClassicyScreenSaverConfigForm.tsx` (122 lines) is not generic: saver-bound props, ids built from `saver.id` (:57), a flat shape and a patch-object `onChange`. Decision: extract, not reuse.

This section (plan 0012-pt9 §1.1) creates `src/SystemFolder/SystemResources/SchemaForm/` with `ClassicySchemaFormFields.ts` (`unwrapClassicySchemaField`, `classicySchemaFieldId`, `classicySchemaFieldLabel`) and `ClassicySchemaForm.tsx`, a recursive form that renders nested `z.ZodObject`s as `ClassicyControlGroup`s and leaves exactly as today (boolean → checkbox row, number → spinner, enum → pop-up, string → input row), reporting changes with the full path. The ScreenSaver form becomes a thin wrapper that keeps ids `ScreenSaver_<saverId>_<key>` and the `{ [key]: value }` patch shape.

**Impact:** J 3.1's Options tab is generated by this form; without it the Options tab has nothing to render. A regression in ids or patch shape would break the Screen Saver control panel's existing tests and persistence.

## Steps

### 1: Write the failing tests in ClassicySchemaForm.test.tsx

Test code:
```ts
const schema = z.object({ on: z.boolean().describe('Enabled'), speed: z.number().min(1).max(9), mode: z.enum(['a','b']), name: z.string(), nested: z.object({ depth: z.number() }).describe('Nested group') })
it('renders one control per leaf with prefixed ids', () => { render(<ClassicySchemaForm schema={schema} values={{ on: true, speed: 3, mode: 'b', name: 'x', nested: { depth: 2 } }} idPrefix="T" onChange={vi.fn()} />); for (const id of ['T_on','T_speed','T_mode','T_name','T_nested_depth']) expect(document.getElementById(id)).not.toBeNull() })
it('uses .describe() as the label and humanizes bare keys', () => { …; expect(screen.getByText('Enabled')).toBeInTheDocument(); expect(screen.getByText('Speed')).toBeInTheDocument(); expect(screen.getByText('Nested group')).toBeInTheDocument() })
it('reports changes with the full path', async () => { const onChange = vi.fn(); …; fireEvent.change(document.getElementById('T_nested_depth')!, { target: { value: '7' } }); expect(onChange).toHaveBeenCalledWith(['nested','depth'], 7); fireEvent.change(document.getElementById('T_mode')!, { target: { value: 'a' } }); expect(onChange).toHaveBeenCalledWith(['mode'], 'a') })
it('spinner takes min/max from the schema', () => { …; expect(document.getElementById('T_speed')).toHaveAttribute('min', '1'); …('max', '9') })
it('classicySchemaFieldLabel', () => { expect(classicySchemaFieldLabel('cellHeight')).toBe('Cell height'); expect(classicySchemaFieldLabel('x', 'Given')).toBe('Given') })
```

### 2: Run them to verify they fail

`pnpm exec vitest run src/SystemFolder/SystemResources/SchemaForm` — Expected: FAIL — module not found.

### 3: Implement ClassicySchemaFormFields.ts and ClassicySchemaForm.tsx per the Interfaces block

`ClassicySchemaFormFields.ts`: `export type ClassicyUnwrappedField = { schema: z.ZodType; description?: string }`; `export const unwrapClassicySchemaField = (field: z.ZodType): ClassicyUnwrappedField` (moved `unwrapField` verbatim from `ClassicyScreenSaverConfigForm.tsx:16-29`); `export const classicySchemaFieldId = (idPrefix: string, path: readonly string[]): string` → `[idPrefix, ...path].join('_')`; `export const classicySchemaFieldLabel = (key: string, description?: string): string` → description, else `key` split on camel-case humps, first letter upper-cased (`cellHeight` → `Cell height`). `ClassicySchemaForm.tsx`: `export type ClassicySchemaFormValues = Record<string, unknown>`; `export type ClassicySchemaFormProps = { schema: z.ZodObject<z.ZodRawShape>; values: ClassicySchemaFormValues; onChange: (path: readonly string[], value: unknown) => void; idPrefix: string; path?: readonly string[] }`; `export const ClassicySchemaForm: FunctionalComponent<ClassicySchemaFormProps>` — iterates `schema.shape`; a nested `z.ZodObject` (after unwrap) renders `<ClassicyControlGroup label={classicySchemaFieldLabel(key, description)}>` containing a recursive `ClassicySchemaForm` with `path=[...path, key]` and `values={values[key] ?? {}}`; leaves render exactly as today (boolean → checkbox row, number → spinner with `field.minValue ?? 0` / `field.maxValue ?? undefined`, enum → pop-up, string → input row), ids from `classicySchemaFieldId(idPrefix, [...path, key])`, `onChange([...path, key], value)`; unsupported kinds render nothing. Keep the row components the ScreenSaver form uses (`ClassicyControlGroupFormRow`, `ClassicySpinner`, `ClassicyPopUpMenu`, `ClassicyInput`, `ClassicyCheckbox`) so the Screen Saver control panel renders the same DOM.

### 4: Rewrite ClassicyScreenSaverConfigForm.tsx as the wrapper; regenerate barrels

`ClassicyScreenSaverConfigForm` becomes `({ saver, config, onChange }) => saver.configSchema instanceof z.ZodObject ? <ClassicySchemaForm schema={saver.configSchema} values={config} idPrefix={`ScreenSaver_${saver.id}`} onChange={(path, value) => onChange({ [path[0]]: value })} /> : null`. Keep its doc comment (it describes the rows) pointing at `ClassicySchemaForm`. Then `pnpm exec barrelsby -c .ts-barrel.json`.
