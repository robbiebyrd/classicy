# Date & Time Manager Sync Button Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Sync button to the Date and Time Manager control panel that sets the Classicy clock from the host machine, with an opt-in `syncTimeOnly` mode that preserves the displayed calendar date.

**Architecture:** A new `ClassicyManagerDateTimeSync` reducer case reads the machine clock and writes both `dateTime` and `timeZoneOffset` in one Zustand state write. The existing min/max clamp inside `ClassicyManagerDateTimeSet` is extracted into a shared `applyDateTimeWithBounds()` helper so Sync inherits bounds handling. A new `syncTimeOnly` store field, seeded by host apps through `ClassicyAppManagerProvider`'s `defaultState`, selects time-only mode. The control panel gains a bottom flex row holding Sync beside the existing Quit button.

**Tech Stack:** React 19 + TypeScript, Zustand store with an event-prefix reducer, Vitest + jsdom + @testing-library/react, SCSS co-located with components, Biome for lint/format.

**Spec:** `docs/superpowers/specs/2026-07-25-datetime-sync-design.md`

## Global Constraints

- Package manager is **pnpm**. Run tests with `pnpm test`, lint with `pnpm lint`.
- `pnpm test` does **not** type-check. Run `pnpm build:source` (which runs `tsc -b`) before considering the branch done.
- Do **not** hand-edit `index.ts` barrel files — they are generated by `pnpm generate-barrels`.
- All styling goes in the co-located `.scss` file. No inline styles, no Tailwind.
- Store `dateTime` is always a **UTC ISO string**; `timeZoneOffset` is a **string of hours** (e.g. `"-4"`).
- `vi.setSystemTime()` fakes `Date.now()` and `new Date()` but **not** `Date.prototype.getTimezoneOffset()`, which comes from the process TZ. The suite pins no TZ, so tests must **derive** expected offsets from the runtime rather than hard-coding them.
- Biome reformats untouched files repo-wide. Scope any `pnpm lint:fix` to the paths this plan touches.
- Commit after each task.

In `ClassicyDateAndTimeEventHandler.ts`, add this function above `classicyDateTimeManagerEventHandler`:

```ts
/**
 * Clamp `date` into the configured [minDateTime, maxDateTime] window, store it
 * as a UTC ISO string, and update boundaryLocked.
 *
 * Shared by ClassicyManagerDateTimeSet and ClassicyManagerDateTimeSync so both
 * honour host-configured bounds identically.
 */
function applyDateTimeWithBounds(ds: ClassicyStore, date: Date): void {
	const { minDateTime, maxDateTime } = ds.System.Manager.DateAndTime;
	const isoValue = date.toISOString();

	if (maxDateTime !== null && isoValue >= maxDateTime) {
		ds.System.Manager.DateAndTime.dateTime = maxDateTime;
		ds.System.Manager.DateAndTime.boundaryLocked = true;
	} else if (minDateTime !== null && isoValue < minDateTime) {
		ds.System.Manager.DateAndTime.dateTime = minDateTime;
		ds.System.Manager.DateAndTime.boundaryLocked = false;
	} else {
		ds.System.Manager.DateAndTime.dateTime = isoValue;
		ds.System.Manager.DateAndTime.boundaryLocked = false;
	}
}
```

Then replace the body of the `ClassicyManagerDateTimeSet` case (everything after the `hasDateTime` guard) with a call to it, so the case reads:

```ts
		case "ClassicyManagerDateTimeSet": {
			if (!hasDateTime(action)) {

				);
				break;
			}
			applyDateTimeWithBounds(ds, action.dateTime);
			break;
		}
```

- [ ] **Step 3: Write the minimal implementation**

Add this case to the `switch` in `classicyDateTimeManagerEventHandler`, after `ClassicyManagerDateTimeTZSet`:

```ts
		case "ClassicyManagerDateTimeSync": {
			const dt = ds.System.Manager.DateAndTime;
			const now = new Date();
			// Sync always adopts the host machine's offset, so the synced hour
			// reads as real local time regardless of what was selected before.
			// Fractional zones (e.g. India, +5.5) are stored faithfully; the
			// timezone pop-up lists whole hours only and will show no selection.
			const newTz = -now.getTimezoneOffset() / 60;
			// Shift into the new local frame so UTC getters yield machine
			// wall-clock fields, independent of the browser's own timezone.
			const nowLocal = new Date(now.getTime() + newTz * 3600000);

			const localMs = Date.UTC(
				nowLocal.getUTCFullYear(),
				nowLocal.getUTCMonth(),
				nowLocal.getUTCDate(),
				nowLocal.getUTCHours(),
				nowLocal.getUTCMinutes(),
				nowLocal.getUTCSeconds(),
				0,
			);

			dt.timeZoneOffset = String(newTz);
			applyDateTimeWithBounds(ds, new Date(localMs - newTz * 3600000));
			break;
		}
```
